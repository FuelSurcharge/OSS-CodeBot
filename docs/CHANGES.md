# 変更案の確認・選択適用・取り消し

## GUI

「ファイル」で参照内容を添付し、「修正提案」を選んで送信する。
回答の「変更案を確認」を押すと、構造化された変更案を読み込み、差分を表示する。
ヘッダーの「変更」からJSONを直接読み込むこともできる。
モデルが必要な形式で回答しない場合はエラーを表示し、書き込まない。

ファイルごとの変更箇所を選択し、「選択した差分をプレビュー」で確認する。
選択・作業フォルダを変更すると以前の確認を解除する。
取り消し用の変更記録は作業フォルダの外へ保存する。既定はOS標準のアプリ設定ディレクトリの`changes/`。
差分と作業フォルダの確認欄をチェックし、「表示した差分を適用」を押した時点で書き込む。
ファイル処理はバックグラウンドで実行し、AIの処理中は適用できない。

取り消す場合は、変更記録から逆向きの差分を表示し、確認して実行する。
直前に操作したフォルダと記録の場所は設定に保存するため、再起動後も取り消しを選べる。
適用・取り消し後は古い参照内容と送信用履歴を無効にする。次の要求ではファイルを選び直す。

## CLI

`--workspace`と`--proposal`で差分を表示する。既定では書き込まず、AIへの接続も行わない。
`--select ファイル番号:変更番号`は1始まりで繰り返し指定でき、省略時は全変更を選ぶ。
`--apply --journal 作業フォルダ外の新規JSONパス`を加え、確認入力`apply`で適用する。
`--undo 記録JSONパス`は逆向きの差分を表示し、同様に確認して取り消す。
非対話実行の`--yes`は明示的な確認省略。プレビューには不要。

## 変更案の形式

versionが1のJSONオブジェクトと、1〜32件の`changes`を受け付ける。
回答全体がJSONの場合と、完結したJSONコードブロックがある場合に対応する。上限1 MiB。

| operation | 必須項目 | 内容 |
|---|---|---|
| create | path, content | まだ存在しないファイルの追加 |
| replace | path, expected_sha256, edits | 既存ファイルの行範囲置換 |
| delete | path, expected_sha256 | 既存ファイルの削除 |

`edits`は`first_line`・`last_line`・`content`の配列で、行番号は1始まり・両端を含む。重複範囲は拒否する。
`expected_sha256`は参照時のファイル全体のSHA-256で、選択行だけのハッシュではない。
参照内容の送信時にこのハッシュを含める。JSONで指定されていないフィールドは拒否する。

## 適用と復元の制約

- 作業フォルダ内の相対パスのみ。親参照、絶対パス、シンボリックリンク、隠しファイル、秘密ファイル、予約名を拒否し、ディレクトリへの権限を限定した入出力を使う。
- ignore規則を適用する。UTF-8テキスト64 KiBまで、一覧2000件まで。追加先の親ディレクトリは先に存在している必要がある。
- 差分表示後と書き込み直前に内容・属性を再確認する。更新前の改行形式と未コミットの内容を保存し、外部編集との競合時は停止する。
- 最大16 MiBの変更記録に原本を保存・同期してから書く。同名の記録を上書きしない。記録にはファイル本文があるため、保管場所に注意する。
- 各ファイルは一時ファイルから置き換える。新規追加は既存ファイルを上書きしないhard link操作を使い、非対応のファイルシステムでは失敗する。
- 複数ファイルの途中失敗時は記録から適用済みの変更を戻す。復元に失敗した場合は記録の場所を表示する。電源断を含めた複数ファイル全体の原子的な更新は保証しない。
- 未完了の記録からも適用済みのファイルを判別して取り消せる。適用後に別の編集が入ったファイルは上書きせず、競合として停止する。

Linuxで共通コア・CLIの競合、選択適用、途中失敗、取り消しをテストし、GUIで選択適用と再起動後の取り消しを実操作した。
モデルが正しい変更案を生成する精度、他OSの実操作、特殊なファイルシステムは未検証。
