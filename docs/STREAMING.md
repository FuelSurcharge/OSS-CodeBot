# 回答の逐次表示と停止

GUIはAPIとローカルAIの回答を受信した部分から表示する。
生成中は送信ボタンが青地に白い停止アイコンへ変わる。
別チャットへ移動しても回答は元のチャットへ追加し、停止操作は実行中の要求へ適用する。
途中のMarkdownやコードブロックも表示できる。

停止・通信切断・タイムアウトは、それまでの回答と状態を画面に残す。
これらの未完了の要求は送信用履歴に含めない。
処理終了後は次の入力を送れる。再試行は同じ参照内容を使い、別の下書きがある場合は保持して通知する。
チャット保存を有効にしている場合は、生成中の部分回答を500ms以上の間隔で保存する。
生成中にアプリを閉じた場合、次回起動で中断を表示する。

CLIは`--stream`を付けると逐次表示し、標準出力を都度フラッシュする。
`--interactive --stream`ではCtrl+Cで今回の生成を止め、次の入力を待つ。
入力待ちでCtrl+Cを押すと終了する。単発実行では停止後に終了する。
`--stream`を省略した従来の一括表示も使用できる。

## 通信とローカル実行

- OpenAI互換は`stream: true`のSSE、Claudeはtextイベントと`message_stop`、Geminiは`streamGenerateContent?alt=sse`を使う。
- UTF-8のネットワーク途中分割、複数行のdata、LF/CRLF、コメントを処理する。表示対象はテキストで、思考用フィールド・ツール呼び出しは表示しない。
- 正常な終端を受けずに接続が切れた場合は未完了として扱う。エラー本文・認証情報は診断メッセージへ転記しない。応答全体の上限は4 MiB。
- キャンセルはHTTPの接続待ち・本文読み込みを中断し、接続を閉じる。既に送信された要求の課金や提供元側の処理停止を保証するものではない。
- llama.cppは同じOpenAI互換SSEを使う。TransformersはTextIteratorStreamerと停止条件を使い、ハートビートの送信で切断を検知して次の生成ステップで停止する。実行中のGPUカーネル自体の即時停止は行わない。
- ローカルCLIは要求ごとに所有するエンジンを終了する。GUIはモデルを保持し、要求を止めた後も使用できる。アプリ終了時は所有するエンジンを終了する。
- `application/json`を返す接続先は従来の一括回答として読み込む。SSE未対応の接続先へ自動再送はしない。

## 検証

模擬HTTPサーバーで4形式の送信内容・履歴ロール・途中到達・日本語分割・終端・切断・タイムアウト・キャンセル時の接続終了を検証。Responsesの不完全な終端では途中回答を保持し、成功扱いにしない。
GUI状態テストでチャット切替・遅延イベントの除外・次の要求・中断した保存内容の復元を確認。
Linuxの実CLIでSIGINT後の次ターンを、実GUIで生成途中・別チャットからの停止・再試行を確認。
Transformersの任意検証は`tests/create_fixture.py`の合成モデルと`tests/check_streaming.py`で、実際のCPU生成・切断による生成停止・スレッド解放・次の生成を確認する。
学習済みモデルの品質、各社の実API認証、実際のllama.cppモデル、他OSの操作とGPUは未検証。
