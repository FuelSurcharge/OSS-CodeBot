# APIのモデル一覧と接続確認

設定画面の「モデル一覧を取得」はGETの一覧要求だけを送信する。チャット本文や添付は送らず、生成要求も行わない。
取得したIDを選択でき、手入力も維持する。一覧に出ない別名・契約専用モデルについて、利用不可とは断定しない。
ClaudeとGeminiのページ送りに対応し、10ページ・1000件を上限にする。上限に達した場合は一覧が不完全であることを表示する。

「指定モデルへ送信して接続を確認」は生成要求を行う。
画面に処理先・モデル・URL・設定の出力トークン上限と料金が発生する可能性を表示し、確認欄を選んでから送信する。
固定の診断入力`Reply OK.`だけを送る。生成結果の本文は表示・保存せず、HTTP応答が選択したプロトコルの生成形式であることを確認する。
出力予算は設定値を使う。1トークンの出力を受け付けないモデルもあるため、極小の値を強制しない。
受理成功はモデル品質や将来の要求成功の保証ではない。安全フィルター等で本文がない場合も、接続・要求受理と回答品質を区別する。

認証不正、権限不足、モデル不明、レート制限、接続・TLS、タイムアウト、応答形式不一致を分けて表示する。
提供元の生のエラー本文は転記しない。自動再試行は行わない。
確認中は中止できる。モデル・接続先・キーを変更すると古い結果・料金の確認を無効にし、古い要求から遅れて届く結果を破棄する。
キー・結果・モデル一覧は通常の設定に保存しない。選択したモデルIDは「API設定を保存」で保存できる。

## CLI

`--config 設定TOML --list-models`で一覧をJSON表示する。
`--config 設定TOML --test-api`は送信先・モデル・出力上限と料金の注意を表示し、`test`入力で実行する。
`--yes`はこの生成要求への明示的な確認省略。確認なしではネットワークへ生成要求を送らない。
