# [CB-013] アプリからGitHub Issue・Pull Requestを扱えるようにする

<!-- codebot-task:CB-013 -->

- 優先度: P1（GitHub連携）
- 状態: 完了（2026-11-09。本番GitHub認証・投稿、他OS実画面は未検証）
- 依存: CB-012
- 根拠: 初期設計書FR-007とPhase 3「Issue・Pull Request連携」

これはCodeBotアプリ本体にGitHub連携を追加するタスク。開発管理用のIssue登録作業とは別に、利用者のリポジトリのIssue/PRを開発コンテキストとして扱う。

完了条件:

- [x] 認証と対象リポジトリを選択し、Issue/PRの一覧・本文・差分を読み込める。
- [x] Issueから作業ブランチを準備し、選択したIssue本文をチャットへ取り込める。
- [x] Issue作成・PR作成・コメント投稿の本文と送信先をプレビューし、利用者の操作で投稿できる。
- [x] 権限不足、レート制限、通信切断、重複投稿を扱う。トークンをログや通常の設定ファイルへ保存しない。

実装: 共通`github.rs`、GUIのGitHub画面、CLIの`--github-*`。[操作・権限・重複記録・制約](../GITHUB.md)。
Rustテスト93件・workspaceビルド成功。ローカル模擬HTTPでIssue/PR取得・本文/差分・3種類の投稿・HTTPエラー分類・切断/不正成功応答・キー/本文の非保存・確認前の無通信・別プロセス間の重複拒否を検証。
Linux実GUIで模擬Issue/PR本文と差分、既存下書きの保持と資料追加、自動送信なし、`issue-42`の確認付きブランチ作成、Issue作成・コメント・下書きPR作成を各1回だけ投稿したことを模擬サーバーと照合。未追跡ファイル保持、接続設定へのキー/本文の非保存、送信記録3件の成功と番号を確認。1180×800と700×540で表示確認。
本番GitHubへの認証・投稿、Enterprise実機、Windows/macOS GUIは未検証。通信制限のため本番APIには到達できていない。重複防止は同じ操作内容のSHA-256と永続記録によるもので、内容を変更した再投稿や別キャッシュ間をGitHub側で一意にするものではない。結果不明の投稿は再送せずGitHubの一覧で確認する。
