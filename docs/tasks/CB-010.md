# [CB-010] コード変更の差分プレビュー・選択適用・取り消しを追加する

- 優先度: P1（開発支援）
- 状態: 完了（2026-11-09）
- 依存: CB-008、CB-009
- 根拠: 初期設計書4.2「コードの変更案と実際の変更を区別」「差分を提示」

回答に含まれる修正案を、実ファイルへ反映できるようにする。提案作成と書き込みを分け、実行前に利用者が変更内容を確認する。

完了条件:

- [x] 追加・更新・削除を構造化した変更案として扱い、GUI/CLIにファイルごとの差分を提示する。
- [x] 利用者が対象ファイル・変更箇所を選んで適用でき、承認前にファイルを書き換えない。
- [x] 読み込み後にファイルが変わっていた場合は競合として停止する。作業ルート外の変更を拒否する。
- [x] 適用内容を記録し、既存の未コミット変更を失わず直前の適用を取り消せる。複数ファイルの途中失敗を検証する。

実装: 共通コア`changes.rs`、CLIの`--proposal`・`--select`・`--apply`・`--undo`、GUIの変更画面と確認欄。[操作と制約](../CHANGES.md)。

検証: Rustテスト54件・workspaceビルド成功。選択適用、CRLF保持、追加・削除、競合、作業ルート外・symlink拒否、途中失敗からの復元をテスト。実際のCLIでプレビュー無変更、承認なし中止、選択適用と取り消しを確認。
Linux GUIで2箇所のうち1箇所を適用し、アプリ再起動後に逆差分を確認して取り消し、原本とバイト単位で一致を確認。1180×800と700×540で表示確認。

未検証: モデルの修正精度、Windows/macOSの実操作（CB-016）、特殊なファイルシステム。複数ファイル全体の電源断時の原子性は保証せず、外部の変更記録による復元を提供する。
