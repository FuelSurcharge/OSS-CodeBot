# 継続対話とチャット保存

## GUIの履歴送信

「会話履歴を含める」を有効にすると、そのチャットで成功した入力と回答を次の推論へ送る。
初期値は無効。ルール診断は常に今回の入力だけを処理する。
送信先・モデルの変更後は送信前に履歴送信を無効にして通知する。新しい送信先へ履歴を送る場合は、チェックを再度有効にする。
失敗・中断した要求は送信用の履歴へ含めない。別チャットの履歴・下書きを混ぜない。

「送信用の履歴を消去」は画面の会話を残したまま、次回送信に使う履歴を空にする。
設定の`max_context_chars`は入力と履歴を合わせたアプリの文字数予算（既定64000）。`max_input_chars`は今回の入力の上限。
これはトークン数の推定ではない。使用モデルのトークン上限・出力予約も別途適用される。
予算を超えた場合は送信前に通知し、下書きを残す。

## CLIの対話モード

```sh
cargo run -p codebot-cli -- --config config/api.example.toml --interactive
```

1行を1要求として扱う。`/clear`で履歴消去、`/trim`で最古の1往復を削除、`/quit`または`/exit`で終了。
EOFでも終了する。空行は送信しない。失敗した要求は履歴へ残さず、対話を継続する。
対話モードでは入力と履歴を設定済みの処理先へ送る。従来の引数・標準入力による単発実行は継続して利用できる。
CLIの対話履歴は終了時に消去する。ローカル推論は現在、CLIでは要求ごとにエンジンを起動・終了する。
`--stream`を追加すると逐次表示とCtrl+Cによる生成停止を使える。[動作と制約](STREAMING.md)。

## チャットの保存・整理

設定の「チャットの保存と管理」で、ローカル保存を選択できる。初期値は保存しない。
空欄の場合の保存先はOS標準の設定フォルダ内`chats.json`。絶対パスを指定して保存先を変更できる。
保存を無効にしても既存ファイルは保持する。保存済みの会話と下書きは次回起動に復元するが、履歴送信の同意は引き継がない。
会話に含めた参照ファイルの内容も保存対象になる。APIキーとHFトークンは保存対象に含めない。

- 設定から現在のチャット名を変更できる。サイドバーと狭い画面のメニューで名前・本文を検索できる。
- 削除操作は対象名を表示して再確認する。要求中は削除できない。最後の1件を削除すると空チャットを作る。
- 現在のチャットをMarkdown/JSONで書き出せる。既存ファイルの上書きは初期値で許可しない。アプリの保存・設定ファイルは書き出し先に指定できない。
- 保存は同じフォルダの一時ファイルへ書き込み・同期後に置換する。容量・権限エラーを表示する。
- 不正なJSON、未知のバージョン、不正な履歴、8 MiB超過は読み込まず、元ファイルを自動上書きしない。退避・修復後に設定から再試行できる。

## 検証範囲

ローカル模擬HTTPサーバーでOpenAI互換・Gemini・Claudeの複数ターンを確認。
実CLIで履歴の継続・削減・消去・失敗したターンの除外を検証した。
Linux CPUで小型のランダム重みsafetensorsモデルを使い、Transformersの2ターン生成を確認した。学習済みモデルの品質の検証ではない。
Linux仮想GUIで保存済みチャット・別チャットの下書き復元、履歴の明示的送信、自動保存、1180×800と700×540での表示を確認。
各社の実API認証やWindows/macOSのGUI実機検証は含まない。
