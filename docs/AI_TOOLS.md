# Responses APIと確認付きツール相談

## Responses API

OpenAIまたはカスタムAPIの設定で「OpenAI Responses」を選択します。既存のOpenAI Chat Completions設定の初期値は変わりません。TOMLでは `[api] protocol = "responses"` を指定します。[設定例](../config/responses.example.toml)。接続先に `/responses` を追加し、`input`で会話履歴と `max_output_tokens` を送ります。`store=false`を指定し、`previous_response_id`によるサーバー側履歴の再利用は行いません。提供元のログやデータ保持条件は契約先に従います。

通常のGUIチャットとCLIの `--stream` に対応します。`response.output_text.delta`・拒否テキストを逐次表示し、`response.completed`で完了します。`response.incomplete`・`response.failed`・切断・タイムアウトは失敗として途中回答を保持し、成功した送信用履歴へ含めません。JSON応答も `status=completed` の場合だけ成功にします。思考用の項目は表示しません。

## GUIからAIに作業を相談

「実行 → AIに作業を相談」を開きます。現在のチャットの下書きと選択済み添付の内容をコピーします。元の下書きは残り、通常のチャット履歴は自動で引き継ぎません。作業フォルダ、相談内容、送信先URL・モデル・形式を確認してから相談を開始します。APIサービスと対応するモデルの設定が必要です。

この相談では次の2つだけをモデルへ提示します。

- `codebot_propose_changes`：version 1の構造化変更案。既存の差分プレビュー・変更選択・確認付き適用へ渡します。更新/削除には元ファイル全体のSHA-256が必要です。参照するファイルは事前に「ファイル」画面で選択して添付してください。
- `codebot_run_command`：実行ファイル・引数配列・1〜300秒のタイムアウト。作業場所は利用者が選んだフォルダに固定し、追加の環境変数をモデルから要求できません。既存のコマンド確認画面で、実行場所・引数・環境変数名・上限を確認します。既定の出力上限は256 KiBです。

受け取った要求だけではファイル変更やコマンド実行は始まりません。差分またはコマンドを確認して実行するか、提案を拒否します。変更案の一部だけを適用することもできます。利用者が画面で内容を編集した場合は、編集後の操作を確認して実行します。

実行・拒否・失敗・停止の結果を表示した後、**結果をAIへ送る確認は別の操作**です。結果を確認して送ると同じ相談の続きを問い合わせます。送信するコマンド結果は既知の秘密値を伏せた最大12,000文字で、切り詰めを表示します。未知の秘密値が含まれないことを保証する機能ではないため、表示した結果を確認してください。ファイル変更の結果は適用したファイル数等の要約で、回復用journalの本文は送りません。

相談を終了しても適用済みの変更や実行済みコマンドは自動で取り消しません。変更案の回復記録は通常の「変更」画面へ引き継ぐため、アプリ再起動後も取り消しを確認できます。コマンドの副作用は変更案の取り消し機能の対象外です。

## 接続先・履歴・上限

相談を始めた接続先・モデル・認証情報と作業フォルダをその相談で固定します。設定や別チャットへ移っても、途中の相談を別のAPIへ自動で引き継ぎません。相談の画面には実際の送信先を表示します。変更する場合は相談を終了して新しく始めます。

ツール相談は通常のチャット保存とは独立し、起動中だけ保持します。要求・結果・認証情報を通常の設定や専用ログファイルへ保存しません。CLIの出力と利用者がコピーした内容は利用者の管理対象です。回答と要求の引数は表示しますが、提供元のHTTPエラー本文は表示しません。

1回の相談につき最大4件のツール要求、最大8回の生成通信、同時に1操作を扱います。同じ引数の要求や識別子の再利用は循環とみなして止めます。引数の形式・長さ・タイムアウトを検証し、実行時にも既存のファイル境界・ハッシュ・実行ファイルの変更検知を適用します。応答は4 MiB、結果は12,000文字、履歴やツール定義を含む送信JSON全体は設定の文字数予算以内です。

ツールの引数は応答が完成して検証できた後に確認画面へ渡します。この相談画面では生成応答を完成後に表示し、通常チャットのストリーミング表示とは別に扱います。問い合わせの停止はHTTP待ちも中断します。実行中のコマンドは既存の「処理を停止」で止めます。ファイル適用の途中停止は提供せず、回復記録付きの既存の適用処理を使います。

コマンドは現在のユーザー権限で動き、作業フォルダ外のファイルや外部通信へアクセスする可能性があります。作業場所の指定はOSの隔離環境ではありません。プレビューした実行ファイルと引数を確認してください。詳細は[コマンドの制約](COMMANDS.md)と[変更案・回復記録](CHANGES.md)を参照してください。

## 対応する形式

OpenAI互換の`tool_calls`/`tool`、Responsesの`function_call`/`function_call_output`、Claudeの`tool_use`/`tool_result`、Geminiの`functionCall`/`functionResponse`を共通の要求・結果へ変換します。IDの対応と、後続要求に必要なClaudeの署名やGeminiのthoughtSignatureなどはメモリ内の履歴で保持します。Responsesの相談では`include=["reasoning.encrypted_content"]`を指定して、保存しない推論コンテキストも後続要求へ引き継ぎます。これらの思考用項目を利用者向け回答へ混ぜません。

対応対象は上記2種類のクライアント側関数ツールです。提供元のWeb検索・computer use・サーバー側組み込みツール、同時複数呼び出し、未完成のツール生成は受け付けません。モデルやゲートウェイによってツール対応が異なります。HTTPエラーでは選択した形式のツールをモデルが扱えるか確認するよう案内し、内容が不明な要求を実行しません。

## CLI

```sh
codebot-cli --config /absolute/api.toml --workspace /absolute/project --tools "この作業の手順を提案してください"
```

初回の入力は引数で指定します。要求後、コマンドには `run`、変更案には `apply` と入力して実行します。異なる入力では拒否として扱います。その後の結果返送には別途 `send` が必要で、それ以外の入力では結果を送らずに終了します。`--yes`によるツール確認の一括省略は提供しません。Ctrl+Cで問い合わせまたはコマンドを中止し、結果を自動送信しません。

変更記録はOS標準のアプリ設定ディレクトリの `changes/` に保存します。`--tools-journal-dir /absolute/recovery`で別の保存先を指定できます。作業フォルダの外である必要があります。CLIは提示した変更案全体の適用/拒否を扱い、部分選択はGUIまたは通常の `--proposal --select` を使用します。

## 検証

ローカル模擬HTTPで4形式の要求・結果・ID・署名の維持、拒否、失敗結果、入力検証、権限項目の追加拒否、循環・ID再利用・操作数/通信数/文字数上限、通信待ちのキャンセルを確認しています。Responsesの通常応答・履歴・SSE途中表示と途中終了も検証しました。
実CLIでは提案拒否、コマンド実行後の返送拒否、確認付き実行と返送、変更案の拒否と確認付き適用、回復記録の保存を模擬APIと照合しました。
Linux実GUIでも同じ流れを操作し、確認前に実行されないこと・結果の返送が別操作であること・元の下書き保持を照合しました。再起動後に通常の変更画面でツールの変更だけを取り消し、コマンドの副作用を保持しました。1180×800・700×540で表示確認しています。
本番の各社API認証・モデル互換性、Windows/macOS実画面は未検証です。
