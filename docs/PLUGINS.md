# 権限を明示する拡張機能 v1

CodeBotのコアを変更せずに、渡したテキストの解析や確認付き操作の提案を追加できます。v1は **WASIと外部importを使わないWebAssembly** を採用します。wasmiのインタープリターで実行し、ホストのファイル・環境変数・APIキー・ソケット・プロセス起動機能をゲストへ渡しません。

## 導入・実行・削除

GUIの「実行 → 拡張機能 → 拡張を導入」で、配布フォルダの `manifest.json` を指定します。「要求する権限を確認」で名前・バージョン・説明・権限・モジュールのSHA-256と保存先を確認し、確認欄を選んで導入します。導入後は無効の状態です。

一覧で拡張を選択して有効にし、作業フォルダと入力を確認して「選択した拡張に入力を渡す」を押します。現在のチャットの下書きと選択済みの参照ファイルは、画面を開くときにコピーします。元の下書きは保持します。入力や結果をAIへ自動送信しません。拡張の結果はプレーンテキストで表示し、リンク・画像の外部読み込みは行いません。

同梱の[入力の行数](../plugins/input-lines/manifest.json)は、渡した入力全体のLFによる行数を数えます。選択したファイルを含む場合、参照情報のヘッダー等を含む入力全体の行数です。アプリのビルド後、サンプル拡張の実行に追加のRust・Python環境は必要ありません。

無効にすると次の呼び出しを止めます。有効な拡張もアプリ起動時に自動実行しません。拡張の削除は対象の登録データを確認して実行します。元の配布フォルダと作業フォルダのファイルは残します。適用済みの変更や実行済みコマンドは自動で取り消しません。変更案の取り消しは通常の「変更」画面で確認できます。

## 権限の意味

| manifestの権限 | 渡せるデータ・提案 | 実行の境界 |
|---|---|---|
| `read-selected-files` | 利用者が選び、プレビューして添付したファイルの内容 | 任意のパスをゲストから読み込むAPIは提供しない |
| `propose-changes` | 構造化したファイル変更案を1件返す | 差分・変更選択・確認付き適用と回復記録を使う |
| `propose-command` | 実行ファイル・引数・タイムアウトの提案を1件返す | 作業場所・引数・環境変数名を確認して実行する |
| `network` | 直接の通信要求 | v1は未対応。要求する拡張は導入できない |

入力欄へ書いたテキストは、その拡張へ渡します。参照ファイルを添付するには `read-selected-files` が必要です。添付は既存の作業フォルダ読み込みの除外・サイズ・パス制限を通したスナップショットで、実行時に未選択のファイルを追加取得しません。

権限を持つ拡張も、ファイル変更やコマンドを直接実行できません。JSONの提案を返し、CodeBotが権限と引数を検証した後、既存の[変更確認](CHANGES.md)・[コマンド確認](COMMANDS.md)へ渡します。モデルと同じ共通形式を使います。未許可の操作や未対応ツールは拒否します。

コマンドの提案を許可する場合、確認したコマンドは現在のユーザー権限で動きます。ファイル操作・外部通信が可能で、作業場所の指定はOSの隔離環境ではありません。コマンドを実行する段階で、実行ファイルと引数を確認してください。追加の環境変数を拡張から要求できません。既定は最大300秒・出力256 KiBで、確認画面から利用者が明示的に編集できます。

## 保存・整合性

OS標準のアプリ設定ディレクトリの `plugins/<id>/` に、次の3ファイルをコピーします。

- `manifest.json`：導入時に確認したメタデータと権限。
- `plugin.wasm`：SHA-256を確認したモジュール。
- `state.json`：有効状態、対応バージョン、確認したmanifestのハッシュ。

入力と結果はこれらのファイルや専用ログへ保存しません。拡張画面で編集した入力と結果は起動中だけ保持します。元のチャット下書きには、通常のチャット保存設定を適用します。
登録内容・モジュール・権限の変更を検知した場合は実行を止めます。SHA-256は整合性の確認で、配布者の署名・作者の認証ではありません。導入前には配布元と内容を確認してください。

導入・状態変更・削除はOSの排他ロック、ゲスト実行は共有ロックで保護します。別のCodeBotプロセスで実行中の拡張を更新・削除しようとすると拒否します。削除確認後の内容変更も拒否します。登録フォルダに管理外のファイルがある場合は削除せず、退避を案内します。

## 実行上限と失敗

モジュールは1 MiB、manifestは64 KiBまでです。入力はUTF-8で64,000文字・256 KiB、出力JSONは1 MiB、表示テキストは64,000文字までです。導入数は200件までです。

ゲストのリニアメモリは64 MiB、テーブルは10,000要素・1個、メモリとインスタンスは各1個までです。検証と管理にはホスト側のメモリも使用します。
実行開始から合計10,000,000 fuelの実行量予算を設けます。無限ループ等は予算を使い切った時点で停止します。秒単位の厳密なwall-clock期限は提供しません。外部I/Oの待機を発生させるimportは許可しません。

ゲストのtrap・不正ポインター・サイズ超過・メモリ拡張失敗・実行量超過は、その呼び出しのエラーとして扱います。ほかの機能と次の拡張呼び出しを継続できます。実行の中止要求は、実行量の上限以内で処理を終了して結果と操作提案を破棄します。導入・削除・ファイル適用は、それぞれの保存・回復処理を完了させます。

## CLI

```sh
codebot-cli --plugin-install /absolute/package/manifest.json --plugin-preview
codebot-cli --plugin-install /absolute/package/manifest.json
codebot-cli --plugin-list
codebot-cli --plugin-enable input-lines
codebot-cli --plugin-run input-lines --workspace /absolute/project "解析する入力"
codebot-cli --plugin-disable input-lines
codebot-cli --plugin-remove input-lines --plugin-preview
codebot-cli --plugin-remove input-lines
```

導入は `install`、削除は `remove` の入力で確認します。`--yes`はこの2つの確認を明示的に省略します。`--plugin-dir /absolute/store` で別の保存先を選べます。有効化・無効化は実行を伴いません。

`--plugin-run`は結果と操作提案を表示します。初期値では提案を実行しません。`--plugin-review`を付けると、既存の個別確認フローでコマンドには `run`、変更案には `apply` を要求します。`--yes`で操作提案の確認をまとめて省略することはできません。
変更記録の保存先は `--plugin-journal-dir /absolute/recovery` で指定でき、作業フォルダの外である必要があります。`--attach relative/path --line-start 1 --line-end 20` で選択した参照ファイルを追加できます。結果をAIへ送る処理はこのモードには含めません。確認した操作が失敗・中止した場合は、結果を表示して失敗終了します。提案を拒否した場合は操作せず正常終了します。

## 拡張作者向け API v1

配布単位は同じフォルダの `manifest.json` と `plugin.wasm` です。manifestの実例は[同梱サンプル](../plugins/input-lines/manifest.json)を参照してください。

| 項目 | 条件 |
|---|---|
| `manifest_version` / `api_version` | どちらも整数の1 |
| `id` | 1〜64文字。先頭は小文字英字か数字、以降は小文字英数字・`-`・`_`。Windows予約名を除外 |
| `name` / `version` | 表示名100文字以内、バージョンは64文字以内の英数字・`.`・`-`・`_`・`+` |
| `description` | 2,000文字以内 |
| `module` | `plugin.wasm` 固定。リンクや別パスは受け付けない |
| `sha256` | モジュールの実際の64桁SHA-256 |
| `permissions` | 上記権限の配列。重複・未知の権限は拒否 |

Wasm32のモジュールで、外部importを使わず、次をexportします。管理処理ではバイトコードの検証・コンパイルだけを行い、ゲストコードは入力を渡す段階で実行します。start関数にも同じメモリと実行量の制限を適用します。

| export | 型 | 処理 |
|---|---|---|
| `memory` | 32bitリニアメモリ | 入力・出力の受け渡し |
| `codebot_alloc` | `(i32 length) -> i32 pointer` | 入力を置く領域を確保する |
| `codebot_run` | `(i32 pointer, i32 length) -> i32 output_pointer` | 入力を処理し、出力JSONの位置を返す |
| `codebot_result_len` | `() -> i32 length` | 出力JSONのバイト数を返す |

入力はNUL終端を持たないUTF-8テキストです。ファイル添付がある場合はCodeBotの参照ヘッダーと本文を含むテキストに合成します。ポインターと長さの範囲はホストが確認します。各呼び出しに新しいインスタンスを用意するため、前の入力やゲストの状態を引き継ぎません。

出力は以下の形のJSONです。`text`は必須、`proposal`はnullまたは1つの提案です。

```json
{"text":"処理結果","proposal":null}
```

提案には `name` と `arguments` を指定します。対応する名前は `codebot_propose_changes` と `codebot_run_command` です。引数は[共通ツールの仕様](AI_TOOLS.md)と[変更案のJSON](CHANGES.md)を参照してください。識別子はホストが付けます。利用者が確認・実行した結果をゲストへ自動で戻す機能はv1には含めません。

`codebot_propose_changes`の引数は `{"proposal": {"version":1,"changes":[...]}}` です。`codebot_run_command`は以下の形です。`propose-command`をmanifestに宣言し、利用者が実行内容を確認する必要があります。

```json
{"text":"テスト実行を提案します。","proposal":{"name":"codebot_run_command","arguments":{"program":"cargo","args":["test","--locked"],"timeout_seconds":120}}}
```

サンプルの[guest.rs](../plugins/input-lines/guest.rs)を修正して再ビルドする場合:

```sh
rustup target add wasm32-unknown-unknown
python scripts/build_sample_plugin.py
```

ビルドはWasm32・cdylib・panic=abort・最適化・シンボル除去を指定し、manifestのSHA-256も更新します。ホストへ独自コードやPython依存をインストールする必要はありません。本体・サンプルのライセンス決定と配布手順はCB-017で追跡します。

## 検証範囲

Rust製の同梱サンプルを実際にコンパイルし、CLIで確認付き導入・有効化・入力と選択ファイルの処理・無効化・削除を別プロセス間で検証しています。模擬Wasmで未許可のファイル/コマンド提案、WASI import、直接通信権限、無限ループ、trap、メモリ超過、不正ポインターを検証しました。失敗後に別の拡張を呼び出せること、ハッシュ/権限の変更検知、確認後の削除内容変更、入力の非保存も確認しています。
Linux実GUIでは導入前の権限表示、導入直後の無効状態、有効化・2行の日本語入力処理・無効化・再起動後の復元・削除を確認しました。別の変更提案用拡張でも、承認前にファイルを作成しないこと、既存の差分確認と適用で指定した1ファイルだけを作成すること、取り消し記録と元のチャット下書きを保持することを実GUI・CLIで確認しています。通常の変更画面から取り消して、元からあったファイルが残ることも確認しています。通常サイズと700×540で実画面を撮影しました。
Windows/macOS実画面、署名付き配布・自動更新・マーケットプレイスは未検証または対象外です。
