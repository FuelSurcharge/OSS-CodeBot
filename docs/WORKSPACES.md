# 参照ファイルとコード説明・レビュー

## GUI

ヘッダーの「ファイル」から作業フォルダを指定し、一覧を読み込む。
ファイル、開始行、終了行を選択し、「選択範囲をプレビュー」で送信する内容を確認する。終了行0は末尾を表す。
「この内容を現在のチャットに添付」で、プレビュー時点の内容を下書きに添付する。まだ送信しない。
チャットの添付表示でファイル名・行範囲を確認し、不要なものは外してから送信する。

「コード説明」「エラー調査」「コードレビュー」を選べる。
指摘のファイル名・元の行番号・理由・修正案と、事実と推測の区別を求める共通指示を付ける。
回答の`codebot-file:相対パス#L行番号`形式のMarkdownリンクをクリックすると、選択した作業フォルダ内の該当行を表示する。
生成結果の正確性を保証する機能ではない。指定範囲外のコードは参照しない。

要求が失敗した場合は回答下の「再試行」で同じ参照内容を再送できる。別の下書き・添付がある場合は保護のため送信を止める。
参照先の内容が変わった場合はファイル画面で選び直してから送る。
作業フォルダが変わると以前の送信用履歴・添付を消去する。参照ファイルを追加した際も履歴送信を無効にし、明示的に選び直す。

## CLI

```sh
# まずプレビューだけを出力する。AIへは接続しない。
cargo run -p codebot-cli -- --workspace /path/to/project --attach src/main.rs --line-start 1 --line-end 20 --action review --preview

# 選択した処理先へ送る。
cargo run -p codebot-cli -- --config config/api.example.toml --workspace /path/to/project --attach src/main.rs --action explain
```

`--attach`は最大8件まで繰り返せる。`--action`は`explain`・`diagnose`・`review`。
`--line-start`の既定は1、終了行の省略は末尾。複数添付の場合は同じ範囲を各ファイルへ適用する。
送信前にファイル・行範囲を標準エラーへ表示するが、ファイル内容を診断ログへ書き出さない。
現段階のファイル添付は単発CLI実行に対応し、`--interactive`との併用は受け付けない。

## 読み込みの制約

- .gitignoreと標準的なignore規則を適用する。隠しファイル、.git、target、node_modules、.env系、秘密鍵などは既定除外する。
- UTF-8の通常テキストのみ。バイナリ、不正な文字コード、64 KiBを超えるファイルは読み込まない。ファイル一覧は2000件まで。
- ファイルは作業フォルダ内の相対パスで指定する。親ディレクトリ参照・絶対パスを拒否し、シンボリックリンクを追わない。
- エラー時は未選択の内容を自動で添付しない。異なるフォルダの添付を一つの要求へ混在させない。
- 添付後の入力全体に`max_input_chars`、履歴を含む全体に`max_context_chars`を適用する。長すぎる場合は送信前に止め、行範囲を減らせる。
- コード・ログ・差分は資料として扱い、その中の指示を実行しないよう求める。ファイル変更やコマンド実行は行わない。

検証は模擬APIを使った処理・表示・引用操作の確認。各AIモデルのレビュー精度を確認したものではない。
