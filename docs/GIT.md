# Gitの状態・差分と確認付き操作

## GUI

ヘッダーの「Git」で作業フォルダを指定し、「状態と差分を読み込む」を選ぶ。
現在のブランチ・HEAD、未追跡・変更済み・ステージ済み・競合を表示する。
ファイルの`[XY]`はGitの状態で、Xがステージ、Yが作業ファイル。`??`は未追跡。
差分は未ステージとステージ済みに分けて表示し、コピーできる。

操作ごとに「確認」を選ぶと、新しく取得した状態を基に対象を表示する。
対象・ブランチ・差分の確認欄を選び、「確認したGit操作を実行」で実行する。
選択・コミット文・ブランチ名等の変更で以前の確認を解除する。

- ステージ/解除：一覧で対象を選択する。初回コミット前の解除も作業ファイルを残す。
- ブランチ作成：現在のHEADから新しいブランチを作って切り替える。初回コミット前にも対応する。
- コミット：ステージしたファイル名からコミット文を提案でき、編集もできる。対象ブランチとステージ済み差分を表示してから実行する。
- push：設定済みのリモートと送信先ブランチを選ぶ。送信元・送信先、最大100件のコミット、差分を表示する。強制pushは行わない。

pushの差分はローカルの追跡情報を基にする。追跡情報がない場合は最大100件の履歴差分を表示する。
リモートの最新状態は送信時にGitが確認し、進んだブランチへの通常pushが拒否された場合は通知する。
自動fetch・merge・rebase・resetは行わない。
実行後は状態を再読み込みし、該当フォルダの古い参照ファイルと送信用履歴を無効にする。画面の会話・下書き・作業ファイルは保持する。

## CLI

`--workspace 作業フォルダ --git-status`で状態・ブランチ・差分をJSONで表示する。
`--git-operation 操作JSONのパス`は操作対象と現在の状態・差分を表示し、`git`入力で実行する。
`--git-preview`を付けると表示だけで終了する。`--yes`は確認の明示的な省略。

操作JSONは`operation`と以下の項目を使う。未知の項目・1 MiB超の入力は拒否する。

| operation | 項目 |
|---|---|
| stage | paths：選択した相対ファイルパスの配列 |
| unstage | paths：選択した相対ファイルパスの配列 |
| create-branch | name：新しいブランチ名 |
| commit | message：コミット文 |
| push | remote：設定済みリモート名、branch：送信先ブランチ名 |

Ctrl+CまたはGUIの中止でGitプロセスへ停止を通知する。
中止のタイミングによってGit側の操作が完了済みの場合もあるため、状態を再読み込みして確認する。

## 保護と対応範囲

- 確認後にHEAD・ブランチ・差分・index・リモート・追跡情報が変わった場合は停止し、確認し直す。ステージ対象の実ファイル内容も照合する。
- パスは作業ルート内の通常の相対パス。`--literal-pathspecs`でファイル名をGitのパターンとして解釈しない。親参照・絶対パス・.git内のパスを拒否する。
- worktreeの.gitファイル、初回コミット前、detached HEAD、競合を扱う。detached HEADからのpushと競合中のコミットは止める。
- 作業ファイルを自動resetしない。ステージ解除はindexだけを変更する。コミット対象は既にステージされた内容で、他の未コミット変更は取り込まない。
- リポジトリ設定による任意のコード実行を避けるため、フック・fsmonitor・外部diff・textconv・GPG署名・clean/processフィルターを無効にする。LFS等のフィルターが必要なファイルはアプリ内でステージせず、外部Gitで処理する。署名やフックが必要なコミットも外部で行う。
- pushは既存のGit資格情報・SSH agent・プロキシ設定を使用する。対話入力は使用しない。認証・権限・利用制限・ネットワーク・ロック等の失敗を通知し、エラー本文やURL内の認証情報を画面へ転記しない。
- HTTPS/HTTP/SSH/fileと通常のローカルパスを対象とし、ext形式や独自ヘルパーを使うリモートは受け付けない。リモートの追加・資格情報の登録は外部Gitで行う。
- ファイル一覧は2000件、各Git出力は4 MiB、ステージ照合は1ファイル8 MiBまで。UTF-8以外のパスや制御文字を含むパス、特殊なフィルター等は外部Gitで操作する。
- GUIは長い差分を行単位で表示し、1行8000文字超は表示を省略する。コピーは取得した全体を対象とする。差分やGit状態を自動でAIへ送信しない。

## 検証

Linuxの隔離した実Gitリポジトリで、初回コミット前のステージ/解除、対象選択、ブランチ作成、コミット、worktree、detached HEAD、競合保持、確認後の変更拒否、フックとフィルターの抑止、URLの認証情報除外をテストした。
認証等のエラー分類には模擬メッセージを使用する。ローカルbareリモートへのpushを実行し、既存の未コミット変更の保持と追跡情報変更後の再確認を検証した。
実CLIで確認前の無変更・確認後の選択ステージを確認。
実GUIで選択ステージ・ブランチ作成・コミット文の提案・差分確認・コミット・ローカルへのpushを行い、未追跡ファイルと下書きの保持を確認した。1180×800と700×540で表示確認。
GitHubへの認証・push、Windows/macOSの実機GUI、特殊なフィルターや署名は未検証。
